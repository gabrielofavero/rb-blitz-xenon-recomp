# Xenia Canary `80679bc` baseline

This is the commit-safe summary of the Rock Band Blitz comparison run performed on 2026-09-07. It records reproducible facts and observations without including the game, emulator binary, logs, or screenshots.

## Scope

The purpose of this run was to establish reference behavior before ReXGlue bring-up. It was not a compatibility investigation or an attempt to fix Xenia.

## Configuration

Xenia ran in portable mode. A fresh configuration was generated by this build, then only these values were changed:

```toml
[Content]
license_mask = 1

[HID]
keyboard_mode = 1
```

The first XBLA license was enabled for the authorized dump. Keyboard controller emulation was enabled because no physical controller was connected.

Relevant unchanged defaults were:

```toml
[APU]
apu = "any"

[GPU]
gpu = "any"
readback_resolve = "none"

[General]
apply_patches = true

[Kernel]
apply_title_update = true
```

No patch pack, plugin, or title update was installed. Xenia selected Direct3D 12 with the ROV render-target path and XAudio2.

## Procedure

1. Place the authorized dump matching `config/game_fingerprints.toml` outside version control.
2. Extract the identified Xenia release into an isolated directory and add `portable.txt` beside the executable.
3. Launch Xenia once to generate its defaults, apply the two configuration changes above, and relaunch `game/default.xex`.
4. Wait for the animated Rock Band Blitz logo.
5. Confirm the keyboard-backed controller connects in slot 0.
6. Send repeated Start (`X`) and A (`;`) inputs while the Xenia window has focus.
7. Observe for several minutes and close Xenia normally.

## First blocker

The first user-visible blocker is an indefinitely looping animated Rock Band Blitz logo. The process remains responsive and continues rendering rather than crashing.

The final notable guest/runtime events before the loop were:

- four failed lookups for unimplemented `XamVoiceSetMicArrayIdleUsers`, ordinal `0x48C`;
- an undefined extern call to `XeKeysSetKey` at `0x827F6BA4`;
- an undefined extern call to `XeKeysAesCbc` at `0x827F6BB4`.

These events correlate with the stall but are not proven causes. Do not copy them into ReXGlue as stubs merely to silence warnings; first determine whether execution depends on their results.

The result is behind the [historical Xenia report](https://github.com/xenia-project/game-compatibility/issues/1533), which reached menus and gameplay but lacked the note tracks and 3D background. Plausible differences include a Canary regression, title/update revision, configuration, or the unresolved key-service behavior.

## ReXGlue comparison targets

This baseline gives the initial recompilation effort concrete checkpoints:

1. Match Xenia's successful XEX identification and base HDR access.
2. Match the intact, animated title-logo rendering.
3. Inventory `XamVoiceSetMicArrayIdleUsers`, `XeKeysSetKey`, and `XeKeysAesCbc` before guest launch, while treating their relevance as unresolved.
4. Improve on this baseline by reaching the offline prompt and main menu.
5. Once gameplay is reached, explicitly test the historical missing-highway/background rendering issue.
